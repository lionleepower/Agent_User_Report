# 实验详解：问了什么、怎么比、怎么判、结论是什么

[English](WALKTHROUGH.en.md) · [完整报告](REPORT.zh-CN.md) · [小白手册](HANDBOOK.zh-CN.md)

这份文档回答面试官最常问的几个问题：**你具体问了什么？比较了哪些方案？它们各有什么特点？对错是怎么判的？最后推荐什么？** 先看评测流程和真实示例，再看每个实验的卡片。

> 示例题目、答案要点和标准段落改编自公开笔记 [CS-Notes](https://github.com/CyC2018/CS-Notes)（作者 CyC2018，CC BY-NC-SA 4.0），模型回答是实验原始输出的节选。这些示例按相同许可共享，仅用于非商业展示；完整题库没有收录。

## 1. 一道题是怎么被评测的

![一道题的完整旅程](figures/eval-pipeline.svg)

用大白话说：

1. **准备一道题**：从笔记的某一段出题，同时记下“标准答案在哪一段”和 2–4 个“答案要点”。
2. **给模型找资料**：这一步就是我们要比较的。整包是把全部资料都给它；BM25、向量、PageIndex 是从资料里挑几段给它。
3. **让模型回答**：规则很严，只能根据给它的资料回答，找不到就必须说“资料中没有相关内容”。这样“资料找错了”会直接变成“答错了”，不会被模型自己的常识蒙混过去。
4. **让另一个模型打分**：对照答案要点给 0、1、2 分。我们最关心“完全正确率”，也就是得 2 分的比例。
5. **算统计**：每道题答两遍先平均，失败算答错，再算出区间，看两种方案的差别是不是真的。

### 题目长什么样

| 题型 | 示例问题 | 答案要点（节选） | 标准答案所在段落 |
| --- | --- | --- | --- |
| 直接问 | TCP/IP 体系结构跟 OSI 分层有什么不一样？ | 只有四层；数据链路层和物理层合并为网络接口层；不严格遵循 OSI 分层 | 计算机网络体系结构 › TCP/IP |
| 换说法 | 在单向链表里删掉一个指定节点，怎么做到平均情况下不用从头遍历就能完成？ | 不是尾节点时把下一个节点的值复制过来，再删掉下一个节点，O(1)；是尾节点时只能从头遍历，O(N) | 在 O(1) 时间内删除链表节点 › 解题思路 |
| 语音噪声 | 嗯 那个踢西批 ip 体系结构跟 哦艾斯艾 分层有什么不一样 | 同“直接问”那道 | 同上 |
| 跨章节组合 | 结合反射与永久代章节，解释 JDK 1.7 及以前大量动态加载类时，Class 信息怎样产生、为何可能触发 Full GC，以及资料给出的处理办法。 | 每个类都有 Class 对象；类在第一次使用时动态加载；永久代存放 Class 信息；类多了永久代会被占满；未配置 CMS 时触发 Full GC；可增大永久代或改用 CMS | 两段：“Java 基础 › 反射”和“Full GC 的触发条件 › 永久代空间不足” |

“换说法”的题故意不用原文里的词（原文叫“删除链表节点”，问题里说“删掉一个指定节点”），专门考检索能不能理解同一个意思的不同说法。“语音噪声”的题模拟语音识别的错字、音译和口头语。

### 同一道题，四种方案答得怎么样（真实输出）

**例 1：简单的直接问题，大家都答对**

问题：“TCP/IP 体系结构跟 OSI 分层有什么不一样？”

| 方案 | 得分 | 回答（节选） |
| --- | --- | --- |
| 整包 | 2 | TCP/IP 只有四层，相当于把五层协议中的数据链路层和物理层合并为网络接口层…… |
| BM25 | 2 | 同上，几乎一字不差 |
| 向量 | 2 | 同上 |
| PageIndex | 2 | 同上 |

问题里的词和原文几乎一样，哪种方案都能找到。简单题拉不开差距。

**例 2：语音噪声让关键词检索失灵**

问题（语音版）：“嗯 那个 互连网和互联网到底有什么区别 就是说 这两个词经常混着用 但好像不是一回事 能解释一下吗”

| 方案 | 得分 | 回答 |
| --- | --- | --- |
| 整包 | 2 | 互连网是把多种不同的网络连接起来，是网络的网络；而互联网是全球范围的互连网。 |
| BM25 | **0** | 资料中没有相关内容。 |
| 向量 | 2 | 互连网是把多种不同的网络连接起来，是网络的网络；互联网是全球范围的互连网。 |
| PageIndex | 2 | 同整包 |

BM25 没找到那一段，很可能是口头语（“嗯 那个 就是说”）把关键词冲淡了；向量按意思找，照样找到了。

**例 3：找到了“半截”，还是答不对**

问题（换说法）：“有个二维数组，每行从左到右递增、每列从上到下也递增，怎么在里面高效找一个目标数？”

| 方案 | 得分 | 回答（节选） |
| --- | --- | --- |
| 整包 | 2 | 从右上角开始找：目标比当前值小就往左走，比当前值大就往下走……O(m+n) |
| BM25 | **0** | 资料中没有相关内容。 |
| 向量 | **0** | 资料里提到了 Leetcode 240 有序矩阵查找，但只给了题目和示例矩阵，没有具体解法。 |
| PageIndex | 2 | 从右上角开始找……最多走 m+n 步 |

记录显示，向量检索其实把标准答案所在的那一段放进了证据，但模型看到的内容里只有“题目和示例”，没有“解法”（解法可能被 2000 字的证据上限截掉了，或者落在相邻的段里），所以模型老实地说“没有具体解法”。这说明**“找到了对的段落”不等于“答对了”**；PageIndex 是按页去读的，这次拿到了完整内容。

**例 4：错字太多，只有翻目录的方法答对了**

问题（语音版）：“嗯 那个 力扣上那道把单练表节点按位置分成两组 先放鸡数位再放偶数位的题 输入1到5会得到什么结果”

| 方案 | 得分 | 回答 |
| --- | --- | --- |
| 整包 | **0** | 资料中没有相关内容。 |
| BM25 | **0** | 资料中没有相关内容 |
| 向量 | **0** | 资料中没有相关内容 |
| PageIndex | 2 | 输入 1->2->3->4->5->NULL，返回 1->3->5->2->4->NULL。 |

“单练表”“鸡数位”把“单链表”“奇数位”念错了。连资料全在眼前的整包都没认出来；PageIndex 答对了，推测是因为它先读目录，从“链表 › 链表元素按奇偶聚集”这样的标题对上了题目。这只是一道题，不能说明 PageIndex 一定更抗错字。

**例 5：跨章节的题，答一半只得 1 分**

上面表格里的“跨章节组合”题，第一遍回答时：

| 方案 | 得分 | 为什么 |
| --- | --- | --- |
| 整包 | 1 | 讲清了永久代和 Full GC，但没讲“Class 对象怎么产生、反射时类怎么加载” |
| BM25 | 2 | 两个章节都覆盖到了 |
| 向量 | 1 | 和整包一样，只答了永久代那一半 |
| PageIndex | 2 | 两个章节都覆盖到了 |

1 分就是“只覆盖部分要点”。这类题只有 12 道，结论只当参考。

## 2. 四种取资料方式的特点和推荐

![四种取资料方式对比](figures/methods-compare.svg)

**怎么选**：资料 6 万字以内直接整包；更大时用向量检索（和 BM25 混合当兜底）；PageIndex 准，但每题慢 5 秒左右，适合不赶时间的场景。

## 3. 每个实验的卡片

下面每张卡片都按同样的顺序写：想回答什么 → 比了什么 → 怎么做 → 结果 → 推荐。第一轮的回答和评分模型是 deepseek-chat（后来已下线），第二轮是 deepseek-flash，两轮的数字不放在一起比。

### 实验 01：资料多大时，整包还靠得住？

- **想回答**：把全部资料直接发给模型，资料到多大会开始答不准？
- **比了什么**：整包、BM25、本地 bge 混合检索、云端 DashScope 向量检索。
- **怎么做**：44 道题，答案都在最前面的 8 篇文档里；不断加入其他主题的文档，让资料从 2.2 万字涨到 12.9 万字；每种大小、每种方法答两遍（每格 88 个回答）。
- **结果**：整包在 8.5 万字以内一直是 75%，12.9 万字时掉到 69%，答错率从 2–5% 升到 10%；DashScope 每档都是 76–77%，没有答错；BM25 一直在 46–47%。
- **推荐**：6 万字以内整包；项目据此把整包上限从 3 万字提高到 6 万字。

![答对率随资料大小](figures/01-accuracy-vs-size.svg)

### 实验 01b：资料都是同一个主题时呢？

- **想回答**：实验 01 加的是无关文档，检索不难。如果加的都是长得很像的同主题文档呢？
- **怎么做**：26 篇结构完全相同的“设计模式”笔记（2.3 → 6.9 万字，22 题）；5 篇 Java 笔记（3.5 → 12.4 万字，54 题）。
- **结果**：设计模式组，整包和 DashScope 都保持 95.5%，BM25 从 59% 降到 50%；Java 组，整包 74% → 70%，DashScope 稳定在 76–78%，本地 bge 混合 72% → 63%。
- **推荐**：同领域资料超过 10 万字后，换成好的向量检索。

### 实验 02：用 LangChain、LlamaIndex 会不会更好？

- **想回答**：主流框架能不能比手写的几百行代码更准？
- **比了什么**：同一份 20 万字资料、48 道题，分别用 LangChain、LlamaIndex 的默认配置和调好的配置重建检索，再和手写实现比。
- **结果**：
  - 两个框架的 BM25 默认配置按空格分词，中文几乎失效，只找到 27% 的正确段落；LangChain 加一行中文分词后升到 81%。
  - 调好后，LangChain 向量 67%、LlamaIndex 77%，和手写实现（69%）同一水平；领先的部分主要来自每次塞给模型更多文字。
  - 两个框架加依赖 103 个 Python 包、346 MB。
- **推荐**：Python 原型可以用；桌面应用、对延迟敏感的产品，手写更合适。

### 实验 03：语音识别的错字有多大影响？

- **想回答**：问题来自语音识别，错字和音译会让检索掉多少？
- **怎么做**：把 48 道题改写成“语音识别的样子”（示例见例 2、例 4）。
- **结果**：找到正确段落的比例，BM25 65% → 52%，本地 bge 混合 88% → 79%，DashScope 94% → 85%；端到端完全正确，BM25 38%，DashScope 60%。
- **推荐**：实时语音场景用向量检索；写资料时把术语的中英文写法都放进标题。

### 实验 04：资料该怎么切段？

- **比了什么**：按标题切 vs 固定长度切；每段 200 / 400 / 800 / 1200 字。只看“正确段落有没有排进前 3”。
- **结果**：按标题切明显更好（DashScope 85% vs 79%）；切到 200 字最差；向量检索在更大的段上更好（85% → 92% → 96%），但区间有重叠。
- **推荐**：按标题切，每段 400 字左右起步。

### 实验 06：每次给模型几段？

- **比了什么**：每次给 3、5、8 段。
- **结果**：5 段比 3 段完全正确率高 6–12 个百分点；8 段没有稳定收益，首字还慢约 0.1 秒。
- **推荐**：5 段，每篇最多 3 段；项目据此从 3 段改成 5 段。

### 实验 07：用哪个回答模型？

- **比了什么**：云端 4 个（deepseek-chat、qwen3.8-flash、qwen3.7-plus、qwen3-8b），本地 5 个（Qwen3 1.7B / 4B / 8B、Apertus-8B、一个推理模型）。
- **结果（节选）**：

| 模型 | 检索场景完全正确 | 首个回答字（检索） | 特点 |
| --- | --- | --- | --- |
| deepseek-chat（已下线） | 70.8% | 0.69 秒 | 快，并发 16 路不变慢 |
| qwen3.8-flash | 85.4% | 1.1 秒 | 更准，但整包时首字约 3 秒 |
| 本地 Qwen3-4B Q4_K_M | 66.7% | 0.27 秒 | 8 GB 显卡可用，免费 |
| 本地 R1 蒸馏推理模型 | 70% | 96 **秒** | 先“想”一分多钟，不适合实时 |

- **推荐**：实时场景选首字快的模型；不赶时间的任务（复盘、写资料）选更准的模型；离线可用本地 4B。

### 实验 07b：用哪个向量模型？

- **比了什么**：bge-small（CPU，24 MB）、Qwen3-Embedding-0.6B（本机显卡）、DashScope（云端）。
- **结果**：找到正确段落 83.3% / 95.8% / 97.9%；语音噪声下 77.1% / 91.7% / 91.7%。
- **推荐**：有显卡用 Qwen3-Embedding，效果和云端持平、免费离线；没显卡用 bge-small 加 BM25 混合。

### 实验 08：让 Agent 自己决定怎么检索，值不值？

- **比了什么**：按 LangGraph 官方教程搭的 Agent（先判断要不要检索 → 判断资料相关吗 → 不相关就改写问题再查 → 回答），对比一次性检索。
- **结果**：完全正确只高约 4 个点，在区间内；改写只在 2–4% 的题上触发；每题 3 次模型调用，端到端 5 秒以上，费用约 15 倍。
- **推荐**：单跳问答不需要 Agent 循环。

### 实验 09：很多人同时问会怎样？

- **结果**：deepseek-chat 在 1–16 路并发下首字都在 0.6–0.8 秒；qwen3.8-flash 首字从 1.3 秒升到 2.5 秒；本地 4 个槽位能同时撑约 4 路实时请求，8 路开始排队。
- **推荐**：小团队共用服务时，选对并发不敏感的云端模型；本地按槽位数规划并发。

### 实验 11：PageIndex（翻目录式检索）到底好不好？

- **比了什么**：整包、BM25、向量、PageIndex，同一个回答模型，检索类最多 5 段、共 2000 字。48 道干净题、48 道语音题、12 道跨章节题，每题答两遍，共 864 次回答；另有 24 次官方原生用法。
- **结果**：

![PageIndex 准确率](figures/11-accuracy.svg)

  - PageIndex 比 BM25 高 21–33 个百分点、比向量高 17–20 个百分点，区间不跨 0，差异可信；
  - 和整包比只高 3–8 个百分点，区间跨 0，**说不清谁更好**；
  - 代价：每题约 4 次请求、6.4 秒、2.8 分钱，整包是 1 次、1.1 秒、0.4 分钱。
- **推荐**：实时场景不用；离线问答、复盘可以考虑。

### 实验 12：缓存能省多少？

- **本地**：KV cache 从 f16 改成 q8_0，启动分配的显存少 46.875%；共享前缀后，短请求的首字从约 0.2 秒降到约 0.04 秒。
- **云端**：开头完全相同的请求命中缓存后，整包的输入费用降约 96%，但首字没有稳定变快。
- **推荐**：提示词把不变的内容放前面，变化的问题放最后；开始前发一个小的预热请求。

### 附加：让 AI 帮你写资料

- **做了什么**：写了一份给外部 AI 用的“资料编写提示词”，拿两份真实岗位描述测了三轮。
- **结果**：6 个资料包都没有编造经历；覆盖面随规则迭代提升（整包完全正确率 20% → 37%、43% → 60%）；“每节末尾加一行关键词”没有帮助，已删除。

## 4. 这些结论的局限

- 每组 22–54 题，一两个百分点的差别不要当真；
- 出题、回答、评分都用同一家的模型，没有人工复核评分；
- 语音噪声是模型模拟的，不是真实录音；
- 只测了中文技术笔记、一台 8 GB 显卡的笔记本、一个网络环境；
- 模型和价格会变，结论只代表实验时的条件。
